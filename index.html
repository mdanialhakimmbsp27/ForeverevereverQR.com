Make your QR links live

One-time setup, easy updates

Choose one way to publish. Each website folder has its own links.json; only QR codes belonging to the selected folder will be published.

⇩

Option A · Download & replace

No account connection. Works with any static hosting provider. Upload the redirect page initially (or when upgrading from an older EverQR version), then replace the link directory after each edit.

First time / upgrading: upload the latest go.html + links.json into the same website folder.
After editing, pausing or deleting: replace links.json.

Keep the same website address and go.html filename. For QR Pause support, replace go.html if you used an earlier EverQR version. Download alone does not publish files. Scan-test after uploading.

↗

Option B · Publish in one click

GitHub Pages only. After one-time setup, change a URL and click Save & publish. No Cloudflare or custom backend needed.

Use a fine-grained token with Contents: Read and write for this repository. The token is never saved in browser storage. The repository must have GitHub Pages enabled. If you host from a subfolder, enter that folder name above; this must match your website URL.

GitHub Pages offers a free github.io address for public repositories. Publication can take time. Your destination URLs in links.json are public.

Why is hosting still needed? A QR code is just an address, not a live database. To replace a destination for everyone, something at the permanent QR address must be updated online. Here that is a small links.json file — no server code is required.
